Primeiro Vídeo

Nesse vídeo o professor explica a diferença entre Git e Github de uma forma bem intrudutória, falando que Git é um software e o Github uma rede social. Em seguida ele explica a importancia do controle de versões e o que é software de controle de versão (VCS), ele mostra também alguns VCS, entre eles o Git, que é um dos VCS mais famosos e completos da atualidade. Algumas vantagens do uso do Git apresentadas no vídeo são:

  1. Controle de histórico
  2. Trabalho em equipe e ramificação (Branching)
  3. Organização e Segurança

Quarto Vídeo

No vídeo o professor Guanabara explica como instalar e configurar o Git e o Github Desktop. Quinto Vídeo

Nesse vídeo o professor Guanabara explica como criar um repositório no Github e como fazer o primeiro commit. Sétimo Vídeo

No vídeo o professor Guanabara ensina como clonar repositórios através do Github Desktop, que inclusive tem uma integração com o site do Github, o que possibilita com apenas um click em um botão (Open in Desktop), dentro do repositório remoto, clonar o repositório em questão. Ele então mostra na prática como clonar um repositório e quando você clona um repositório ele vem de forma integral para o seu computador, com todas as pastas e arquivos. No minuto 19:22 ele comenta sobre como saber se uma pasta é versionada ou não, algumas pessoas podem não saber o que é uma pasta versionada, uma pasta versionada é um diretório onde o conteúdo (seus arquivos de código) está sendo controlado por um sistema de versionamento, como o Git. Quando uma pasta está versionada:

  • Identificação: O Git cria uma pasta oculta chamada .git dentro dela. É essa pasta que armazena todo o histórico e as configurações do projeto.
  • Controle: Você pode gerenciar diferentes versões do mesmo projeto sem precisar criar cópias manuais (como "projeto_final", "projeto_final_v2").
  • Segurança: O sistema permite registrar quem fez a alteração, quando e por que, garantindo maior organização e segurança durante o desenvolvimento.

Nono Vídeo

O que é uma Issue? Nas palavras do Guanabara, nesse vídeo, uma issue é um problema que a comunidade ou alguém indentificou mas ainda não se sabe a solução. Um pull request (pedido para puxar) é quando você descobre alguma solução para a issue e sobe ela no github. Existem várias mótivos para fechar (Closed) uma issue, seja porquê ela foi resolvida, seja porquê era algum span, ou era uma issue duplicada e etc. Para criar uma nova issue basta ir no repositório dentro do github na aba issues e clicar em: "New Issue". Há também como travar os comentários de uma issue, para isso você acessa a página da issue e aperta em: "Lock conversation", aparece um icone de cadeado, lá pede para você escolher o motivo pelo qual trancar o chat. No mesmo lugar onde há como trancar o chat, no lado esquerdo da tela de issues, há também como "pinnar" uma issue e deixar ela fixada no topo da tela da aba de issues; há como transferir uma issue para outro projeto e deletar a issue. No fim do vídeo o Guanabara ensina a configurar Saved Replies (respostas salvas), permitindo que você crie assinaturas ou respostas padronizadas para agilizar a interação no GitHub.

Décimo primeiro vídeo

Décimo segundo vídeo

O vídeo mostra como iniciar um repositório local usando o GitHub Desktop (o que cria a base do versionamento) e como usar a função de Publish para enviá-lo ao GitHub na web, tornando-o público para acesso remoto. O que é uma Branch: É uma ramificação do seu projeto. Pense nela como um "universo paralelo" ou um ramo que sai do tronco principal da árvore, permitindo que você desenvolva novas funcionalidades ou corrija erros de forma isolada, sem afetar o código estável. O que é a Branch Main (antiga Master): É o tronco principal da sua árvore. Representa o código em produção, ou seja, a versão oficial e estável do seu software que está pronta para ser entregue. O que é um Merge: É a operação de junção. Quando você termina o trabalho em uma branch e ela foi testada e aprovada, você utiliza o merge para incorporar essas alterações de volta ao tronco principal (main/master), tornando essas modificações parte da versão oficial. O que é um Origin: É o seu repositório remoto (neste caso, o GitHub). Ele atua como um backup online do seu projeto, onde você envia (push) as suas alterações locais para que fiquem armazenadas e acessíveis remotamente. A resolução de conflitos no Git ocorre quando você tenta realizar um merge (fusão) de duas branches que alteraram a mesma linha de um mesmo arquivo de formas diferentes. O Git não consegue decidir automaticamente qual versão é a correta, então ele pausa o processo e pede uma intervenção humana.

Nesta aula, o professor Guanabara ensina como utilizar o recurso GitHub Pages para hospedar sites estáticos (como projetos em HTML, CSS e JavaScript) de forma totalmente gratuita e direta pelo GitHub. O professor demonstra o passo a passo completo, desde a preparação do projeto local no Visual Studio Code, até a configuração dentro das Settings do repositório, onde é possível ativar o serviço e escolher a branch que será publicada. Ele também reforça a importância de manter o controle sobre o versionamento através de boas práticas, como realizar o merge das alterações da branch de desenvolvimento para a master antes da publicação. Além disso, Guanabara destaca a praticidade de ter uma URL pública para compartilhar seus projetos e explica que, após cada push, existe um pequeno tempo de espera para que as atualizações entrem no ar.
